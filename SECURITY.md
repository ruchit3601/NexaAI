## Vector storage (RAG module)
This project uses an in-memory vector store instead of a persistent vector database (e.g., ChromaDB or a hosted equivalent). This is a deliberate choice: available free hosting tiers either charge past a limited trial credit (Chroma Cloud) or use ephemeral disk storage that doesn't actually persist data between restarts (Render free tier), making "free persistent storage" not genuinely available at this project's scale. Given the app's usage pattern (a user uploads a document and asks questions within one session), an in-memory store is sufficient and avoids paying for or fighting infrastructure that wouldn't provide real persistence anyway. Documents do not survive a server restart — this is a known and accepted limitation, not an oversight.
